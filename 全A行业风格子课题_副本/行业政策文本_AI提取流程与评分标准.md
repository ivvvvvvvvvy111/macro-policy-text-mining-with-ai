# 行业政策文本 AI 提取流程与评分标准

用途：说明行业类政策文本如何从一篇原始文件拆成政策措施、行业对象、作用渠道和事件级评分，并最终聚合为“行业 × 日期 × 政策指标”。

写法：全文使用一个虚构的新能源汽车政策作为贯穿案例。先展示完整流程，再逐步说明每一步的观察单位、数据结构、AI任务、评分标准和聚合方式。

口径：本文所有政策内容和分数均为方法演示，不代表真实政策评价或投资结论。LLM负责结构化抽取和规则化评分，最终因子权重、衰减周期和有效性必须用历史样本检验。

> [!summary] 当前结论
> 行业政策文本不能直接从“一篇文件”压缩成一个利好或利空分数。更合理的最小观察单位是：`政策措施 × 行业对象 × 作用渠道`。政策对象和作用渠道是标签；方向、强度、覆盖范围、执行确定性、持续性、边际变化和新颖性才是评分字段。

## 一、贯穿案例：一份包含两项措施的行业政策

假设政策原文如下：

> 2026年7月1日，某中央部门发布《新能源汽车产业支持通知》。中央财政安排100亿元，对2026年购买符合条件的新能源汽车给予补贴，每辆最高1万元；自2026年10月1日起，提高动力电池安全技术标准。各地方应于8月底前制定实施细则。

这篇文件至少包含两项措施：

1. `M1`：新能源汽车消费补贴；
2. `M2`：提高动力电池安全标准。

其中，`M1`可能通过需求渠道影响新能源乘用车和动力电池；`M2`可能同时通过成本、供给和竞争格局渠道影响不同类型的动力电池企业。因此，整篇文件不能只保留一个“汽车利好”标签。

## 三、步骤0：保存原始政策文件

### 3.1 观察单位与数据结构

观察单位是一篇政策文件。一篇文件占一行，原始文本是该行中的一个长文本单元格。

| policy_id | 标题                   | 发布日期   | 发布机构   | 原始文本     |
| --------- | ---------------------- | ---------- | ---------- | ------------ |
| P001      | 新能源汽车产业支持通知 | 2026-07-01 | 某中央部门 | 完整政策原文 |

数据形状可以表示为：

$$
N_{policy}\times K_{document\ fields}
$$

本例只有一篇政策，因此是`1行 × 5列`。

### 3.2 AI任务

这一步主要是清洗和识别，不评分：

- 识别标题、发布日期、发布机构和文号；
- 保留完整原文；
- 记录市场最早可获得时间，而不只是数据库入库时间；
- 判断是否存在附件、表格或配套文件缺失。

> [!warning] ⚠️ 防止前视
> 回测应使用“市场首次可以获得该文本的时间”。如果文件7月1日已公开、数据库7月3日才抓取，事件日期仍应是7月1日；反过来，也不能用7月10日发布的配套细则倒填7月1日的评分。

## 四、步骤1：将政策文件拆分为措施

### 4.1 为什么必须拆分

同一份政策可能同时包含补贴、税收、准入、限产、技术标准和监管处罚。不同措施可能影响不同对象，甚至方向相反。整篇文件只给一个分数会丢失政策内部结构。

### 4.2 数据结构

| policy_id | measure_id | 措施摘要             | 原文证据                                 |
| --------- | ---------- | -------------------- | ---------------------------------------- |
| P001      | M1         | 新能源汽车消费补贴   | “中央财政安排100亿元……每辆最高1万元” |
| P001      | M2         | 提高动力电池安全标准 | “自2026年10月1日起……”                |

数据关系是：

```text
1篇政策文件
├─ M1：消费补贴
└─ M2：安全标准
```

即政策表与措施表之间是`1:N`关系。

### 4.3 AI拆分规则

满足下列任一条件时，通常应拆成不同措施：

- 政策工具不同，例如补贴与准入标准；
- 目标对象不同，例如消费者与生产企业；
- 生效时间不同；
- 影响方向不同；
- 原文分别规定了金额、数量目标或执行要求；
- 即使属于同一段文字，也存在可以独立执行的动作。

不应仅因为原文分段、标号变化就机械拆分。拆分依据是“是否构成独立的政策动作”。

## 五、步骤2A：识别政策作用对象

### 5.1 这一层回答什么问题

这一层只回答“政策作用于谁”，暂时不判断影响方向。

| measure_id | 一级行业 | 细分对象         | 产业链环节   | 直接性 |
| ---------- | -------- | ---------------- | ------------ | ------ |
| M1         | 汽车     | 新能源乘用车     | 下游整车     | 直接   |
| M1         | 电力设备 | 动力电池         | 中游零部件   | 间接   |
| M2         | 电力设备 | 动力电池全行业   | 中游零部件   | 直接   |
| M2         | 电力设备 | 低端动力电池产能 | 中游低端产能 | 直接   |
| M2         | 电力设备 | 头部动力电池企业 | 中游头部企业 | 直接   |

### 5.2 对象识别不是评分

以下字段属于分类或事实字段，不应打高低分：

- 一级行业、二级行业、三级行业；
- 产业链环节；
- 企业类型；
- 全国或地方；
- 直接或间接；
- 受政策约束或享受政策支持的主体。

这些字段必须使用固定标签表。例如行业名称应映射到申万、中信或项目自建分类，不能允许AI自由创造近义行业名称。

### 5.3 矩阵表示

数据库中建议保存上面的长表；模型处理中可以转换为“措施 × 行业”的多标签矩阵：

| 措施\行业  | 新能源乘用车 | 动力电池 | 充电桩 |
| ---------- | -----------: | -------: | -----: |
| M1消费补贴 |            1 |        1 |      0 |
| M2安全标准 |            0 |        1 |      0 |

这里的`1`只表示“该措施涉及该行业”，不代表正面影响。

## 六、步骤2B：识别作用渠道

### 6.1 什么叫作用渠道

作用渠道回答的是：

> 政策首先改变了行业经营中的哪个变量？

例如：

```text
消费补贴
→ 消费者购车成本下降
→ 新能源汽车需求增加
→ 整车销量和收入可能提高
```

这里首先变化的是需求，因此属于“需求渠道”。

```text
安全标准提高
→ 企业检测、研发和设备改造投入增加
→ 企业成本和资本开支上升
```

这里首先变化的是成本和资本开支。

```text
安全标准提高
→ 不达标产能退出
→ 行业供给收缩、集中度提高
→ 龙头企业市场份额可能增加
```

这里同时涉及供给和竞争格局渠道。

### 6.2 八类核心渠道

| 渠道                                     | 核心问题                         | 典型政策信息                                       | 示例政策措施（方法演示）                                                                                |
| ---------------------------------------- | -------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 需求                                     | 政策是否改变产品或服务需求       | 补贴、政府采购、以旧换新、强制配置、应用场景       | 对符合条件的新能源汽车每辆补贴1万元，首先降低消费者购车成本并刺激销量，因此记为需求渠道。               |
| 价格                                     | 政策是否改变产品售价或定价权     | 限价、指导价、集采、价格补贴、定价机制改革         | 将某类药品集中采购最高中标价下调20%，直接压低产品销售价格，因此记为价格渠道。                           |
| **传导**成本（供给 - 需求 的中间） | 政策是否改变企业经营成本         | 税费、能源、环保、安全、人工、合规成本             | 将符合条件企业的所得税率由25%降至15%，直接降低税费负担，因此记为成本渠道。                              |
| 供给                                     | 政策是否改变产量、产能或供给数量 | 限产、扩产审批、进口限制、淘汰落后产能             | 要求水泥企业在采暖季错峰停产30天，直接减少行业产量和市场供给，因此记为供给渠道。                        |
| 竞争格局                                 | 政策是否改变准入门槛和市场份额   | 资质、技术标准、兼并重组、国产替代<br />强者恒强； | 提高动力电池安全准入标准，不达标企业退出、合规龙头份额可能提高，因此记为竞争格局渠道。                  |
| 资本开支                                 | 政策是否要求或刺激企业投资       | 新建项目、设备更新、技术改造、研发投入             | 对企业设备更新投资给予30%补助，刺激企业购买设备和改造产线，因此记为资本开支渠道。                       |
| 定向融资【政策促进】【减税 -> 政策推动】 | 政策是否改变行业融资条件         | 贴息、专项贷款、担保、产业基金、融资限制           | 为集成电路企业设立500亿元专项低息贷款，直接降低目标行业融资成本并增加资金可得性，因此记为定向融资渠道。 |
| 技术                                     | 政策是否改变技术路线和商业化条件 | 技术标准、研发支持、旧技术退出、商业化许可         | 将新型储能技术纳入示范应用目录，同时停止新增旧技术项目，直接改变行业技术路线选择，因此记为技术渠道。    |

**？**：

1）是否需要加“库存”

2）相当于行业间接变量

如果项目覆盖外贸政策，还可以增加“进出口”渠道；如果监管风险特别重要，也可以单独设置“监管与合规”渠道。

### 6.3 核心关系表

| relation_id | measure_id | 目标对象         | 作用渠道 | 传导逻辑                         |
| ----------- | ---------- | ---------------- | -------- | -------------------------------- |
| R1          | M1         | 新能源乘用车     | 需求     | 补贴降低购车成本，刺激销量       |
| R2          | M1         | 动力电池         | 需求     | 整车销量增加，带动电池装机需求   |
| R3          | M2         | 动力电池全行业   | 成本     | 增加检测、研发和产线改造支出     |
| R4          | M2         | 低端动力电池产能 | 供给     | 不达标产能可能退出               |
| R5          | M2         | 头部动力电池企业 | 竞争格局 | 合规门槛提高，份额可能向龙头集中 |

从这一步开始，最小观察单位正式变为：

$$
政策措施\times 行业对象\times 作用渠道
$$

### 6.4 多渠道如何保存

如果一项措施对同一对象存在多个渠道，应当展开成多行，而不是把多个渠道塞入一个字符串：

| relation_id | measure_id | 对象           | 渠道     |
| ----------- | ---------- | -------------- | -------- |
| R3a         | M2         | 动力电池全行业 | 成本     |
| R3b         | M2         | 动力电池全行业 | 资本开支 |
| R3c         | M2         | 动力电池全行业 | 技术     |

这样才能分别给成本、资本开支和技术影响评分。

## 七、步骤2C：对每条渠道关系评分

### 7.1 评分对象

评分不是针对整篇文件，也不是针对整个行业，而是针对每个`relation_id`。

例如，AI分别评价：

- R1：消费补贴通过需求渠道影响新能源乘用车；
- R3：安全标准通过成本渠道影响动力电池全行业；
- R5：安全标准通过竞争格局渠道影响头部电池企业。

### 7.2 评分结果示例

| relation_id | 方向 | 强度 | 覆盖 | 确定性 | 持续性 | 边际变化 | 新颖性 | AI置信度 |
| ----------- | ---: | ---: | ---: | -----: | -----: | -------: | -----: | -------: |
| R1          |   +2 |    4 |    4 |      3 |      2 |       +2 |      3 |     0.95 |
| R2          |   +1 |    3 |    4 |      3 |      2 |       +1 |      3 |     0.85 |
| R3          |   -1 |    2 |    4 |      4 |      3 |       -1 |      2 |     0.82 |
| R4          |   -2 |    3 |    2 |      4 |      4 |       -2 |      2 |     0.78 |
| R5          |   +2 |    3 |    2 |      4 |      4 |       +1 |      2 |     0.74 |

这些数字仅用于展示数据形状。正式评分必须遵守下面的统一标准。

## 八、各评分维度的具体标准

### 8.1 影响方向：`-2～+2`

！！！：方向和强度并一起

方向必须站在当前`目标对象 + 作用渠道`的角度判断。

| 分数 | 标准                                                         | 示例                                       |
| ---: | ------------------------------------------------------------ | ------------------------------------------ |
|   +2 | 明确且较强的正向影响；传导方向清晰                           | 明确消费补贴直接扩大目标产品需求           |
|   +1 | 一般正向影响，但传导间接、条件较多或幅度有限                 | 下游补贴间接带动上游零部件需求             |
|    0 | 原文明确显示影响中性，或同一条关系内部正负大体抵消           | 价格机制调整但不改变企业收益或成本         |
|   -1 | 一般负向影响，但幅度有限或存在缓冲                           | 增加部分合规成本，但企业有较长整改期       |
|   -2 | 明确且较强的负向影响；可能直接限制需求、价格、供给或经营资格 | 禁止销售、强制退出、显著压价或取消核心资质 |

判断原则：

- 宣传性积极语气不等于`+2`；
- “鼓励、支持、积极推动”如果没有实质工具，最多只能说明政策取向，不能自动判为强正面；
- 同一措施对不同对象可以方向相反；
- 没有足够信息时输出`null`，不能用`0`代替。

### 8.2 政策强度：`0～4`

强度衡量“政策工具对已覆盖对象施加的力度”，尽量不重复计算覆盖范围和执行确定性。

| 分数 | 标准                                                    | 典型文本特征                                       |
| ---: | ------------------------------------------------------- | -------------------------------------------------- |
|    0 | 没有实质性政策动作                                      | 背景介绍、成果总结、一般性倡议                     |
|    1 | 原则性支持或约束，缺少具体工具                          | “鼓励发展”“持续关注”“原则上从严”             |
|    2 | 已明确政策工具，但金额、比例、数量或约束力度有限/未披露 | 明确将补贴、贴息或提高标准，但缺少关键数量         |
|    3 | 工具具体，存在较明确金额、比例、数量目标或强制要求      | 明确补贴标准、税率调整、产能指标或强制门槛         |
|    4 | 政策剂量大、约束强，可能显著改变行业供需或竞争均衡      | 大规模资金、全国性强制标准、核心资质重构、全面禁限 |

需要同时抽取强度证据，例如金额、税率、补贴比例、产能数量、覆盖产品数量和处罚标准。

### 8.3 覆盖范围：`0～4`

？：看IC就行了anyway

覆盖范围衡量政策影响的地区、企业和市场规模，不等同于政策力度。

| 分数 | 标准                                   |
| ---: | -------------------------------------- |
|    0 | 明确不适用于当前目标对象               |
|    1 | 单一试点、极少数地区或极窄产品范围     |
|    2 | 多地试点、部分细分行业或特定企业类型   |
|    3 | 覆盖主要地区、主要产品或行业大部分企业 |
|    4 | 全国性、全行业或几乎全部目标企业       |

如果原文未说明覆盖范围，应输出`null`，不应默认全国，也不应记为`0`。

### 8.4 执行确定性：`0～4`

执行确定性衡量政策是否已具备可执行条件。

| 分数 | 标准                                                           | 典型状态                         |
| ---: | -------------------------------------------------------------- | -------------------------------- |
|    0 | 仅为讨论、研究方向或无法确认的表态                             | “研究考虑”“适时推动”         |
|    1 | 正式规划或原则性意见，但缺少实施工具和责任安排                 | 规划纲要、指导性倡议             |
|    2 | 已发布正式文件和政策工具，但关键资金、细则或流程尚未确定       | 正式通知，但等待地方细则         |
|    3 | 对象、工具、责任部门、时间或资金大部分明确，仅少量细节待补充   | 中央资金明确，地方执行办法待发布 |
|    4 | 已正式生效或具备完整资金、标准、责任部门、流程、考核和处罚机制 | 实施办法已落地并可直接执行       |

建议由下列客观字段辅助判断：

```text
文件是否正式发布
责任部门是否明确
政策对象是否明确
资金来源是否明确
数量目标是否明确
生效时间是否明确
申请/审批流程是否明确
监督、考核或处罚是否明确
```

### 8.5 持续性：`0～4`

？：是政策有效时间？

持续性衡量行业影响维持多长时间，而不是市场当天反应多久。

| 分数 | 标准                                          |
| ---: | --------------------------------------------- |
|    0 | 一次性信息，对行业经营状态几乎不形成持续影响  |
|    1 | 短期，原则上少于3个月                         |
|    2 | 3个月至1年                                    |
|    3 | 1年至3年，或形成较长投资/整改周期             |
|    4 | 长期制度性影响，原则上超过3年或没有明确终止期 |

若政策期限和影响期限均无法判断，应输出`null`。

### 8.6 政策边际变化：`-2～+2`

nope，单一证据单元不能搞；或者搞一个上面几个因子的差分

边际变化必须和上一版政策、上一时间窗口或既有制度比较，不能只看当前文件。

| 分数 | 标准                                     |
| ---: | ---------------------------------------- |
|   +2 | 明显加码、扩大支持或由限制转为支持       |
|   +1 | 小幅加码、补充细则或支持范围有所扩大     |
|    0 | 基本延续原有政策，没有实质变化           |
|   -1 | 支持力度有所下降、条件趋严或政策逐步退出 |
|   -2 | 明显收紧、取消支持或政策方向发生负向转折 |

> [!important] ❗ 需要历史基准
> `policy_delta`和`novelty`不能仅凭当前一篇文本可靠判断。AI必须同时获得上一版政策、既有规则摘要或前一窗口政策状态；否则输出`null`并标记“缺少比较基准”。

### 8.7 新颖性：`0～4`

新颖性衡量这篇文件提供了多少市场此前未知的新增信息。

| 分数 | 标准                                                   |
| ---: | ------------------------------------------------------ |
|    0 | 完全重复已公开内容，没有新增信息                       |
|    1 | 主要重复原有政策，仅有措辞或程序性变化                 |
|    2 | 提供部分新增细节、时间节点或适用范围                   |
|    3 | 引入新的政策工具，或资金、范围、标准发生明显变化       |
|    4 | 政策框架、制度方向或约束机制发生重大且此前未预期的变化 |

新颖性不等于政策强度。强政策如果早已充分预告，新颖性仍可能很低。

### 8.8 起效速度：分类字段

起效速度建议先使用分类，不必强行评分：

| 类别     | 建议定义                                    |
| -------- | ------------------------------------------- |
| 立即     | 发布或生效后约1个月内开始影响经营或交易条件 |
| 短期     | 1—6个月                                    |
| 中期     | 6—18个月                                   |
| 长期     | 18个月以上                                  |
| 无法判断 | 原文缺少生效、执行或传导时间信息            |

如果后续模型必须使用数值，可在回测阶段把类别转换为半衰期或衰减参数，不建议让AI直接主观给出精确天数。

### 8.9 AI置信度：`0～1`

> **！！！ === 证据确信读**

置信度衡量“AI对抽取和判断是否可靠”，不是政策影响有多强。

| 区间       | 标准                                               |
| ---------- | -------------------------------------------------- |
| 0.90—1.00 | 原文直接明确，存在数字、对象、动作和时间证据       |
| 0.70—0.89 | 原文较明确，但需要一步常规产业链推理               |
| 0.50—0.69 | 需要多步传导、对象边界不清或正负影响并存           |
| 低于0.50   | 证据不足、依赖较强外部假设，应进入人工复核或不入库 |

置信度必须和证据句、推理理由同时输出，不能只给一个小数。

## 九、哪些字段不评分

并不是AI提取出来的所有信息都需要转成分数。

| 字段类型 | 处理方式               | 示例                                 |
| -------- | ---------------------- | ------------------------------------ |
| 客观事实 | 原文抽取               | 发布机构、日期、金额、税率、生效时间 |
| 分类标签 | 固定枚举或多标签       | 行业、细分对象、渠道、文件类型       |
| 关系判断 | 分类 + 证据            | 直接/间接、受益/受损、产业链上下游   |
| 评分字段 | 按规则输出分数 + 理由  | 方向、强度、覆盖、确定性、持续性     |
| 比较字段 | 必须有历史基准才能评分 | 边际变化、新颖性                     |
| 缺失字段 | 输出`null`和缺失原因 | 原文未披露金额、未说明执行期限       |

> [!warning] ⚠️ “无信息”不等于“中性”
> `0`表示AI有证据认为影响为零或处于评分最低档；`null`表示原文和比较基准不足，无法判断。两者不能混用。

## 十、步骤2D：政策执行可信度的并行抽取

执行属性以`measure_id`为观察单位，同一措施产生的多个`relation_id`共享这些属性。

| measure_id | 文件状态 | 资金明确 | 责任部门 | 配套细则       | 执行确定性 |
| ---------- | -------- | -------- | -------- | -------------- | ---------: |
| M1         | 正式发布 | 100亿元  | 明确     | 地方细则待发布 |          3 |
| M2         | 正式发布 | 不适用   | 明确     | 技术细则待完善 |          4 |

例如，M1产生R1和R2两条关系。M1的文件状态、资金和实施细则可以通过`measure_id`同时连接到R1和R2，不需要重复调用AI抽取。

## 十一、步骤2E：政策时间结构的并行抽取

| measure_id | 首次公开时间 | 生效日期   | 截止日期   | 预计起效 | 持续类型 |
| ---------- | ------------ | ---------- | ---------- | -------- | -------- |
| M1         | 2026-07-01   | 地方细则后 | 2026-12-31 | 短期     | 临时性   |
| M2         | 2026-07-01   | 2026-10-01 | 未说明     | 中期     | 制度性   |

必须区分三个时间：

```text
信息首次公开时间
→ 政策法律/行政生效时间
→ 行业基本面预计兑现时间
```

三者在很多政策中并不相同。

## 十二、步骤2F：财务映射是否必须

结论：第一版不是必须，第二版建议增加。

- 如果目标只是构造行业政策指标，做到对象、渠道、评分、执行和时间即可；
- 如果需要解释政策为什么影响行业，财务映射很有价值；
- 如果未来要从行业继续映射到上市公司，财务映射基本不可缺少。

| relation_id | 渠道     | 财务/经营变量  |   方向 | 传导逻辑                   |
| ----------- | -------- | -------------- | -----: | -------------------------- |
| R1          | 需求     | 整车销量       |      + | 补贴降低消费者购车成本     |
| R1          | 需求     | 营业收入       |      + | 销量增加可能带动收入       |
| R1          | 需求     | 毛利率         | 不确定 | 仍取决于价格竞争和补贴归属 |
| R3          | 成本     | 研发及检测支出 |      - | 新标准增加合规投入         |
| R3          | 资本开支 | 设备改造支出   |      - | 产线可能需要升级           |
| R5          | 竞争格局 | 龙头市场份额   |      + | 行业门槛提高，份额可能集中 |

财务映射不应直接输出“利润增长10%”之类的伪精确结果。政策文本通常只能支持变量方向和传导逻辑，具体财务弹性需要行业数据或公司数据补充。

## 十五、步骤4：从事件长表聚合为行业指标

### 15.1 不建议一开始只做一个总分

同一行业可能同时受到需求支持、成本上升和监管收紧。如果只保存净值，容易把有信息的正负冲突抵消掉。

第一版至少保留：

- 各渠道正向政策强度；
- 各渠道负向政策强度；
- 正向政策总强度；
- 负向政策总强度；
- 净政策支持度；
- 政策分歧度；
- 政策数量和政策关注度；
- 加权执行确定性；
- 加权新颖性。

### 15.2 两类事件分数

建议区分“政策状态”和“新增政策信息”。设：

- $d$：方向，取值`-2～2`；
- $I$：强度，取值`0～4`；
- $C$：覆盖，取值`0～4`；
- $E$：执行确定性，取值`0～4`；
- $P$：持续性，取值`0～4`；
- $N$：新颖性，取值`0～4`。

政策状态分数可以先采用一个待检验的baseline：

$$
StateScore_r=d_r\times\frac{I_r}{4}\times\frac{C_r}{4}\times\frac{E_r}{4}\times\left(0.5+0.5\times\frac{P_r}{4}\right)
$$

新增政策信息分数可以采用：

$$
NewsScore_r=d_r\times\frac{I_r}{4}\times\frac{C_r}{4}\times\frac{E_r}{4}\times\frac{N_r}{4}
$$

两者区别是：

- `StateScore`反映当前政策环境是否持续支持或约束行业；
- `NewsScore`强调本篇文本相对既有信息带来的新增冲击；
- 一项长期强政策即使新颖性为0，状态分数仍可保留，但新增信息分数应接近0。

> [!warning] ⚠️ 公式只是baseline
> 乘法结构、各维度权重和分数映射都必须通过回测比较。不要因为公式看起来完整，就把它当成已经验证的最优因子。

### 15.3 按行业和渠道聚合

对于日期$t$、行业$i$、渠道$c$：

$$
Positive_{i,t,c}=\sum_r \max(Score_r,0)
$$

$$
Negative_{i,t,c}=\sum_r \min(Score_r,0)
$$

$$
Net_{i,t,c}=Positive_{i,t,c}+Negative_{i,t,c}
$$

示例结果：

| 日期       | 行业     | 需求支持 | 成本压力 | 供给约束 | 竞争改善 | 正向强度 | 负向强度 | 净支持度 |
| ---------- | -------- | -------: | -------: | -------: | -------: | -------: | -------: | -------: |
| 2026-07-01 | 汽车     |    +1.20 |     0.00 |     0.00 |     0.00 |     1.20 |     0.00 |    +1.20 |
| 2026-07-01 | 电力设备 |    +0.68 |    -0.40 |    -0.35 |    +0.55 |     1.23 |    -0.75 |    +0.48 |

上表数值仅演示最终数据形状，不是由示例评分严格计算所得。

### 15.4 防止重复计算

“电池全行业”“低端产能”“头部企业”存在对象重叠，不能在没有权重控制时机械相加。可采用以下方法：

1. 先按渠道分别聚合，不直接跨渠道求总分；
2. 为细分对象增加`industry_exposure_weight`，使用产能、收入或市值占比，而不是由AI凭空估计；
3. 对同一政策、同一行业、同一渠道设置上限或去重规则；
4. 比较`max`、`mean`、`sum`和置信度加权等聚合方式；
5. 最终通过历史回测选择聚合口径。

## 十六、步骤5：最终矩阵和张量

假设共有：

- $I$个行业；
- $T$个交易日；
- $F$个政策指标。

最终数据可表示为三维张量：

$$
X_{i,t,f}=行业\times 日期\times 政策指标
$$

第三维可以包括：

```text
需求支持
价格影响
成本压力
供给约束
竞争格局改善
资本开支影响
定向融资支持
技术支持
正向政策强度
负向政策强度
净政策支持度
政策确定性
政策新颖性
政策分歧度
```

在回测程序中，通常拆成多张“行业 × 日期”矩阵。例如净政策支持度矩阵：

| 行业\日期 | 07-01 | 07-02 | 07-03 |
| --------- | ----: | ----: | ----: |
| 汽车      |  1.20 |  1.08 |  0.97 |
| 电力设备  |  0.48 |  0.43 |  0.39 |

07-02和07-03可以来自信号衰减，也可以来自新的政策事件。是否衰减、采用多少半衰期，必须由回测决定。

## 十七、第一版建议落地字段

第一版建议先完成前四层，不强制加入财务映射。

| 字段组   | 建议字段                                           |
| -------- | -------------------------------------------------- |
| 文件字段 | policy_id、标题、发布机构、首次公开时间、原文      |
| 措施字段 | measure_id、措施摘要、政策工具、原文证据           |
| 行业对象 | 一级行业、细分行业、产业链环节、企业类型、直接性   |
| 渠道关系 | relation_id、作用渠道、因果链、受益/受损对象       |
| 通用评分 | 方向、强度、覆盖、确定性、持续性、边际变化、新颖性 |
| 时间字段 | 生效日期、截止日期、预计起效速度、持续类型         |
| 质量字段 | AI置信度、评分理由、缺失字段、人工复核状态         |
| 版本字段 | 模型名称、prompt版本、行业标签表版本、评分规则版本 |

第一版主流程：

```text
原始政策
→ 拆分措施
→ 映射行业对象
→ 展开作用渠道
→ 对每条渠道关系评分
→ 连接执行和时间属性
→ 形成事件长表
→ 按行业、日期、渠道聚合
→ 构造多张行业政策因子矩阵
```

## 十八、质量控制与人工复核

建议优先复核以下样本：

- AI置信度低于0.70；
- 同一关系同时出现强正面和强负面结论；
- AI没有提供原文证据；
- 需要三步以上产业链传导；
- 行业标签不在固定行业字典中；
- 边际变化和新颖性缺少历史比较文本；
- 同一政策产生过多行业或渠道标签；
- 强度为4但原文没有金额、比例、强制要求或其他强证据；
- 将“鼓励、推动、加强关注”等宣传性措辞直接判为高强度；
- 把`null`错误填成0。

模型效果至少从三层验证：

1. 抽取准确性：措施、行业、渠道、日期和金额是否正确；
2. 评分一致性：相同规则下，不同批次和不同模型的分数是否稳定；
3. 因子有效性：聚合后是否具有合理分布、时间稳定性、IC/RankIC或分组区分度。

## 十九、当前结论

行业政策文本的最合适数据结构不是“一篇政策一个分数”，而是由多张表连接起来的事件数据库：

```text
政策文件表
→ 政策措施表
→ 措施—行业对象表
→ 措施—对象—渠道关系表
→ 关系评分表
→ 行业—日期聚合表
→ 行业政策因子矩阵
```

其中：

- 对象、渠道、时间和政策工具以结构化抽取为主；
- 方向、强度、覆盖、确定性、持续性、边际变化和新颖性按统一规则评分；
